# 审计规则集的编译与原子加载

## 故障描述

值班审计发现：同一份规则声明编译两次得到的加载序列不一致，两台机器上采集到的审计事件对不上；一批规则加载到一半失败，剩余规则留在内核里，后来卸载又清出一个空洞，重启之后规则编号从空洞处继续，排障时对不上任何一份变更单。落点 gsb/batch48-go-safety-d-13 的 audit_rule_set.go，类型 AuditRuleSet，签名保持：NewAuditRuleSet() *AuditRuleSet、NormalizePath(string) (string, error)、ValidateRule(Rule) error、MergeWatches([]Rule) []Watch、Compile([]Rule) (Program, error)、Render(Program) string、Load(Program) ([]int, error)、Unload([]int) error、Active() []int、Rules() []Rule、Snapshot() ([]byte, error)、Restore([]byte) error、Stats() Stats。

要修：路径必须是绝对路径，连续斜杠、结尾斜杠与点段要归一，相对路径直接报错，归一后按区分大小写比较且不跟随符号链接；权限位只允许 r、w、x、a 四个字符，为空或含其它字符拒绝；字段只认 uid、gid、comm、exe、path、auid，未知字段报错；comm 与 exe 只允许等号与不等号，其余字段可用比较符另算，操作符不认识就拒绝，声明为空直接报错；等价 watch 按归一后的路径与权限位合并，过滤条件去重后排序，声明顺序记进索引；排序先按优先级从高到低，再按声明先后，不得依赖 map 遍历，优先级相同的规则只按声明顺序排，不得再按路径字典序调整，已加载的规则再次出现在同一批声明里按冲突处理；编译产物逐字节可复现，同一份声明任意次编译结果一致；加载是整批原子操作，任一条与现有规则冲突则整批不生效，卸载同样原子且任一编号不存在则全部保留；规则编号单调递增，删除之后不复用；通配路径与具体路径并存时具体路径优先，删除具体规则后通配规则立即接管；加载失败后已分配但未生效的规则编号水位也要回退，不能让下一次加载从空洞处续号；快照保留活动规则、编号水位与计数，恢复后继续编号不冲突且不得重发已用编号，统计记录编译、加载、卸载与被拒绝次数。

硬约束：编译与加载都要能并发调用，同一时刻只允许一个批次改写活动规则集；原子性靠先校验后提交两步完成，提交阶段不允许再失败；快照在批次边界产生，恢复过程中不接受新的加载；重启后活动规则与编号水位必须与快照一致；单次加载的 watch 数量与过滤条件总长度受固定上限约束，超出整批拒绝而不是截断。
