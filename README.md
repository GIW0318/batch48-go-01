# 凭据切换顺序与回滚

## 故障描述

交接班时接到一线反馈：一批后台任务以特权身份启动后要降到业务账号运行，可切换完成再查目录权限，补充组少了两个，进程还能读到不该读的共享目录；更糟的是一次切换在半途失败，回滚之后组列表和切换前对不上，业务侧的权限判断连续报错。落点 gsb/batch48-go-safety-d-11 的 process_cred_transition_guard.go，类型 CredTransitionGuard，签名保持：NewCredTransitionGuard(Limits) *CredTransitionGuard、StepOrder() []Step、SetGroupWhitelist([]int) error、Plan(Target, Creds) (Plan, error)、Apply(Plan, bool) (Result, error)、Rollback() error、Inspect() State、Snapshot() ([]byte, error)、Restore([]byte) error、Stats() Stats、AuditLog() []string。

要修：一次降权必须按补充组、主组、用户、环境清理、no_new_privs 五步固定顺序推进，乱序写入要被挡下；目标进程号缺失或不是正数直接报错，补充组里出现负数同样拒绝，计划编号单调递增且重启之后不得回退；每一步执行之前都要判断该步之后是否还能退回原状态，跨过用户切换后即视为不可退回，未显式确认的不可退回计划必须拒绝，且不得留下半步状态；目标进程运行时带多个系统线程时，可退回计划一律拒绝；补充组数量超过配额报错，目标组集合必须落在登记的白名单内，空白名单不允许登记；回滚严格按逆序执行，回滚补充组时要还原原始的组排列，重复项一个都不能少，去重会让最终权限与切换前不一致；no_new_privs 已开启之后再请求切换用户是允许的，但目标权限必须是当前权限的子集，超出范围直接拒绝；环境清理步骤要摘掉继承变量并把清掉的条数记进结果；同一计划重复落地必须报错且状态不变，回滚不可退回的计划必须报错并保留已落地步骤；快照只保留步骤进度、当前凭据与计数，恢复之后不得重放已完成的步骤；损坏的快照必须拒绝恢复且不破坏现网状态；审计记录按发生顺序逐条登记每一步的落地与回滚，统计计数与操作一一对应。

硬约束：同一时刻只允许一个计划处于落地或回滚过程中，计划、落地、回滚三个阶段串行执行，任一步失败都不允许留下半步；快照必须是某一时刻的完整视图，恢复过程中不接受新的计划；重启后凭据状态、已落地步骤与计数必须与快照一致；补充组数量与环境变量清理受配置上限约束，超出上限直接拒绝而不是截断。
